## 現在の学習実験の仕様

語彙の順番は `猫=0, 犬=1, 鳴く=2, 吠える=3`。入力IDは埋め込み表の行、正解IDは高く採点したい出力行列の行を指定する。出力行列は「語彙数×埋め込み次元」。両方の行番号がIDに対応するが、二つの行列の役割は別。

1. 固定の入力ベクトル `x` を取得。
2. `scores = output_weights.matvec(x)`。
3. `prob = softmax(scores)`。
4. 全出力候補の行について `error = prob[i] - target`。正解の行は `target=1`、他は0。
5. `row[j] -= learning_rate * error * x[j]`。

現在は100 epoch、学習率0.1を固定。各epochで全例を逐次更新し、その後、全例を重み変更なしで評価する。損失は `-ln(prob[target_id])`。確率・損失CSVのepoch 0は、初期状態ではなく最初の一周の更新後。

```sh
cargo test
cargo run -- train --profile experiments/basic2.json --verbose weights.csv > training.csv
uv run python scripts/plot_training.py training.csv
uv run python scripts/plot_weights.py weights.csv
```

標準出力は `epoch,input_id,target_id,target_prob,loss`。`--verbose PATH` は任意で、`epoch,row,col,weight` の重み履歴を別ファイルへ書く。履歴は各epoch終了後で、各学習例の更新直後ではない。ファイルは上書き。Pythonはuvのプロジェクト環境を使用し、PEP 723は補完環境との相性のため取りやめた。

## 対話で扱った理解の到達点

### Rustと周辺ツール

本人が内積、行列積、構造体、メソッド、単体テスト、モジュール分割を実装した。所有権のmoveは要素のコピーではないこと、`&[f32]` は配列とVecを借りて受け取れること、`&self` と `&mut self` を扱った。

直近では `iter().flatten().copied().collect()`、自動借用、式全体への `&`、Serde derive/feature、`Vec<String>` と `&'static str`、clap、`main -> Result` と `?`、`Option<Result<...>>::transpose()` と `as_mut()` を説明して実装した。まだ学習中なので理解を前提にしすぎない。

CSVの値はPythonでは文字列。`typing.cast` は実行時変換ではないことを確認し、int/floatで変換するプロットを本人が書いた。

### モデルの計算

トークンIDは語彙項目の番号。埋め込みはその行を読む初期表現で、検索用の文章embeddingとは区別する。通常の推論では学習済み重みを固定し、入力や中間表現が変わる。

出力行列の各行と内部ベクトルの内積が、その出力候補のスコアになる。行列の値に言語的な意味が自然発生するのではなく、正解例に基づく更新で採点を調整する。softmaxは確率化であり抽選自体ではない。argmaxだけならsoftmaxは不要だが、学習や抽選を見据えて実装した。

AttentionではQ/Kの内積から係数を求め、Vだけを加重和する。keyそのものをvalueへ足すわけではない。生成結果のIDを入力列へ足す自己回帰を実装した。

### 微分と更新式

微分・対数・連鎖律を小さな例から説明した。本人は「おそらくわかった」としているが、抽象式とコードの対応で繰り返し確認が必要だった。

- 微分値は、元の関数の出力ではなく、その出力の変化量／入力の変化量の極限。小さな入力変化を出力変化へ換算する倍率。
- 数値微分の有限幅による近似と、導出済み微分式の評価を区別する。コードは小さなhで差分を取っていない。
- `ln(exp(s))=s`、積・商の対数、`exp`の微分、`ln`の微分1/xを扱った。
- `L=-s_target+ln(Z)`、`Z=sum(exp(s_i))`。他スコア固定で `s_i→Z` の変化率はexp(s_i)、`Z→ln(Z)` は1/Z。積がprob[i]となり、最初の項の寄与と合わせて `error=prob[i]-target`。
- 「何を動かし、何の変化率を見るか」を必ず明示する。連鎖律は二回微分ではない。
- `error` はスコアに対する損失の変化率。`error*x[j]` は個別の重みに対する損失の変化率。学習率を掛けて引くのは、損失の増える方向と逆へ小さく動かすため。

重みの符号とスコアの増減が長い間混乱点だった。負の入力なら重みを減らすとスコアが上がる。重みやスコアが正になる必要はなく、候補間の差が重要。同じ入力に対する一行のスコア変化は `-learning_rate*error*sum(x[j]^2)`。ただしこの式だけ示すより、具体的な採点表を追うほうが伝わった。

## 具体的に確認した結果

basicでは猫と犬が別の列を選ぶため更新が干渉しない。100周で両方の正解確率が約0.912になった。一回目の猫の更新は、正解行の0列目が+0.075、他行は-0.025、1列目は変更なし。次の猫の評価は正解約0.269214、他約0.243595。

basic2では両入力が1列目（ゼロ始まり）を共有するため、猫と犬の更新が互いのスコアに影響する。100周時点の正解確率は猫約0.890、犬約0.821。失敗・発散ではなく、basicより進み方が遅い。この例は両方を正しく採点できる。なお `[1,1]` と `[1,-1]` は直交するため、この固定埋め込み・線形出力だけの更新では互いのスコア変化が打ち消し合う。
